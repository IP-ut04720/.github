<h2>路由器上「设代理」和「设参数」是两件事</h2>
<p>家用路由器配置海外出口，有两种完全不同的做法。一种是把 WAN 参数改成住宅提供的地址，整台路由器像在海外上网一样。另一种是在路由器上配置代理客户端，让流量经过代理转发，WAN 仍用本地宽带。</p>
<p>两者的效果、适用场景、排错方式都不同。选错会让配置变得异常复杂。</p>

<p>设备超过三台，逐台配置就开始变得麻烦。此时把配置上移到路由器或旁路由，只维护一份规则，是更合理的选择。</p>

<h2>路由器代理的配置顺序</h2>
<p>第一步，确认路由器支持第三方固件或自带代理功能。第二步，导入或手动填写代理参数，确认协议类型与认证方式。第三步，设置分流规则：哪些目标走代理，哪些直连。第四步，处理 DNS，避免解析泄漏。第五步，逐设备验证。</p>
<p>顺序里第三步最关键。规则写错会出现「该走的没走、不该走的走了」，表现为部分网站打不开、部分应用异常。</p>

<h3>分流规则怎么写</h3>
<p>两种写法。按域名写：列出需要走海外出口的域名，命中即走代理。按来源写：指定某几台设备或某个网段走代理，其余直连。前者精准但需要维护列表，后者简单但粒度粗。</p>
<p>实际使用中常见组合是：按设备选出口，再在出口内按域名微调。这样规则量可控，也便于排查。</p>
<h3>DNS 是成败关键</h3>
<p>只做流量转发不改 DNS，解析结果可能仍指向本地优化节点，导致「连上了但内容不对」。正确做法是让 DNS 请求也走代理，或直接把 DNS 设为目标地区解析服务器。改完用解析查询工具确认。</p>

<h2>旁路由的实际配置</h2>
<p>旁路由本质是一台额外的设备，接在同一个局域网里，承担代理网关的角色。主路由通过 DHCP 下发旁路由为网关，或通过静态路由把目标流量指过去。</p>
<p>三个必配项：旁路由的网关指向主路由（否则它自己上不了网）、旁路由开启流量转发、主路由把目标流量交给旁路由。三项里最容易漏的是第一项，表现为旁路由能配置但完全不通。</p>

<h2>常见故障与对应原因</h2>
<p>故障一，全部设备无法上网。原因多为 LAN 与 WAN 网段冲突，或 DHCP 未正常下发。</p>
<p>故障二，部分设备能上、部分不能。原因多为该设备有固定 DNS 或固定网关，绕过了新配置。</p>
<p>故障三，能打开网页但视频卡。原因多为带宽不足或 MTU 不匹配。</p>
<p>故障四，时断时续。原因多为代理连接数触顶，或路由器性能不足。</p>

<h2>稳定性优化</h2>
<p>三项建议。一，把路由器放在通风处，家用路由器长时间高负载容易过热。二，关闭不必要的插件与云管理功能，减少资源占用与规则干扰。三，设置定时重启或连接保活，避免长时间运行后连接表溢出。</p>
<p>三项都不难，但能显著改善长期稳定性。</p>

<h2>常见问答</h2>
<h3>路由器需要什么配置才够</h3>
<p>代理转发对性能要求不高，但连接数多时内存是瓶颈。设备数超过十台、或需要高并发时，建议用性能更好的设备或软路由。</p>
<h3>能只让部分设备走海外出口吗</h3>
<p>可以，按来源地址分流即可。这是家庭场景最常用的方式，既保留本地便利，又满足特定设备的需求。</p>
<h3>改了路由器影响家人上网吗</h3>
<p>按来源分流不影响，整网改 WAN 会影响。有家人共用网络时，务必用分流方案。</p>
<h3>配置丢了怎么办</h3>
<p>备份配置文件。多数路由器支持导出配置，恢复时一键导入。没有备份的，重配往往要花不少时间。</p>
